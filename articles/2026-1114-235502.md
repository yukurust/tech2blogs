## はじめに

複数の作業を AI に並列で進めさせるため、入口となるエージェントを立てて、そこから全自動で開発が回る仕組みを作ろうとしました。結論から言うと、その自動化は失敗でした。

今は Linear と Orca だけのミニマルな構成に落ち着いていて、やりたかった並列開発自体はできています。この記事では、なぜ自動化を目指して、なぜやめたのかをまとめます。

きっかけは、TECH WORLD のこの動画を見たことでした。

@[youtube](bSlAW71HbBc)

Orca を使った並列開発がすごくて、「これをさらに活用したい」と思ったのが始まりです。どうせなら入口から全部自動で回してしまおう、と考えました。

- **対象読者：** AIエージェントに実装を任せる範囲を広げたい人、複数の作業を並列で進めたい人

## grok bot に命令を送っていた頃

今までの開発スタイルは grok bot に命令を送って Cursor で実装させるものでした。手軽で気に入っていたのですが、このやり方に限界を感じた理由は3つあります。

- 作業を任せるほどトークン使用量が増え、コストが気になってきました
- 頼める量に上限があり、grok bot のレートリミットに達してしまうこと。並列に進めたいときほど、その上限が足かせになりました
- grok bot はほかの用途にも使っているので、エンジニアリング専用の環境を切り分けたかったこと

## 入り口を一つにしたかった

新しい構成でいちばん欲しかったのは、入り口を一つにすることでした。入り口が一つなら、外出先からでも簡単に指示が出せて、開発が楽に回せそうだと思ったのです。それが、Hermes というエージェントを入口に選んだ理由でした。

組んだ仕組みはこうです。相談や計画は Hermes に話し、実装してほしい内容は Linear の issue として登録する。Mac に常駐する bridge が issue を拾って Orca のワーカーに流し込み、ワーカーが worktree で実装して PR を作る。PR ができると2段階の AI レビューが走り、結果が通知される。issue を複数登録しておけば、そのいくつかを同時に実装させられる、という狙いでした。

```
Hermes で相談 → Linear に issue 登録 → bridge が自動検知 → Orca のワーカーが実装 → PR 作成 → AI レビュー → 通知
```

## 作るのが思ったより大変だった

実際に作り始めると、実装そのものより周辺の設計に時間を使いました。

大半を費やしたのは権限の設計です。入口の AI に全部の権限を持たせるのは危険だというところから、使えるツールを許可リストで閉じ、作業の起動権限はホスト側の bridge だけが持ち、認証情報は隔離環境に渡さない、という形に絞り込みました。Issue の本文やコメントは作業の材料であって、命令ではありません。この線引きに一番悩みました。

さらに、並列にした瞬間に部品が増えていきました。同じ issue を二重に起動しないための実行予約、進み具合の通知、PR を読む AI レビュー、それらの変化を見張るウォッチャー。1つずつ順番に進めるだけなら、ほとんど要らないものばかりです。

## それでも自動化はうまくいかなかった

仕組みとしては一通り動くところまで作れたのですが、実用にはなりませんでした。自動で動かしている途中で処理が止まってしまうことがあり、そのたびに原因を追って直すのは自分自身でした。「楽をするための自動化」に、楽にならない手間がかかり続けていたわけで、あまり理にかなっていないと感じるようになりました。

折しも大学の研究などで時間が足りていない時期で、開発環境の維持にこれ以上時間をかける余裕はありません。そこで自動化は諦めて、構成を最小まで削ることにしました。

## 今の構成：Linear と Orca だけ

現在のやり方はシンプルです。Orca では、Linear のプロジェクトごとに共通のエージェントを1つ立ち上げ、そこから issue ごとにサブエージェントを立ち上げて並列に開発させています。入り口の自動化も、橋渡しの部品もありません。

やってみると、結局のところ変わったのは入り口だけで、元々やりたかった「複数の issue を並列に実装させる」こと自体はこれでできています。

## 反省

今回の反省は、仕組みの作り方そのものについてです。AI でいろいろなものが作れるようになった今、全部を自作しようとすると、かえって労力がかかって勿体ないことになります。

既存のサービスが優秀なら、その中で効率よく開発する方法を探すほうがいい。足りないところがあれば、必要に応じて小さなプラグインを開発するくらいがちょうどいいのだと思います。これからはそのくらいの距離感で、道具と付き合っていくつもりです。
